# 签到工具（checkin）交互设计 · 站点签到页

> 状态：设计稿（未实现）｜面向版本：v1.2+（热更通道）｜方法源：frontend-design 技能
> 本文档只给出设计与实施建议，不改动任何源码。

## 0. 一句话结论

签到工具的本质是「**今天签没签**」的每日一瞥工具，不是数据后台。主视图第一眼必须回答"今天签到完成率是多少、谁还没签"，且**新站点接入要做到「改后端、不动前端」**。视觉上放弃通用 SaaS 蓝，用朱印红盖章的「签到簿」身份建立个性。

---

## 1. 设计目标与原则

### 1.1 场景定义（ground in subject matter）

读现状代码 + 用户反馈后，把产品钉死为三个事实：

| 事实 | 含义 | 设计后果 |
|---|---|---|
| 用户**每天只开一眼**，看"签没签" | 高频微任务，10 秒级 | 主视图首屏即答案：今日 N/M + 失败名单，无需滚动 |
| 用户**偶尔管理账号**（新增/换 Cookie/加小号） | 低频深任务 | 编辑走独立弹窗/抽屉，**绝不停留在卡片主路径上** |
| **未来不断加站点**（10+） | 中频结构任务 | 站点元数据单一事实源后移 → 前端零改动接入新站；布局自动退化为可分组列表 |
| 存在**多账号/小号** | 粒度是「账号 × 站点」，不是「站点」 | 卡片状态 = 账号聚合并能展开 | 

核心诉求解构：**扩展性不是"多写几个卡片模板"，而是"新增一种站点类型时，前端一行都不改"。**（详见 §3.3）

### 1.2 产品个性：一页「签到簿」，不是 dashboard

按 frontend-design 方法论，拒绝以下模板 defaults：

- ❌ 暖奶油背景 + 衬线标题 + 陶土色（Anthropic Claude 交互惯用色，套用即"AI 生成味"）
- ❌ 纯黑底 + 酸性绿/朱红单点强调
- ❌ 通栏 hairline + 0 圆角报纸风
- ❌ SaaS 卡片套件：一模一样的圆角卡片 + 统一软阴影 + 渐变 wash
- ❌ 模板级 chrome：全大写 eyebrow、`A · B · C` 中点、`标签 — 说明` 破折号、`#0B0B0B` 假黑、mono 小数据标签、按钮后跟 `→`

**视觉身份定位：数字化『签到簿/台账』+ 『盖章』时刻。**

- **签到的动作语义 = 盖一枚章**（每日打卡、邮戳、印泥），这是本产品独有的、来自签到行业语境的身份符号。
- 主视图是一页**台账**：顶部一行"今日账目"，下面是逐站"结算行"。
- **章只盖一处**（skill 的 boldness-in-one-place）：「今日全部完成」的庆祝瞬间 + 品牌记号 + 主 CTA。其余状态色严守语义、安静克制。
- 这一族不走"可爱贴纸"路线，也不走"企业蓝"路线，走的是**私章朴素**路线：像一本手边的小记事本，偶尔盖个红章。

### 1.3 设计原则（本产品的铁律）

1. **第一眼是答案**：首屏给出「今日已签 N/M」，失败站一眼可数（≥3 站直接列败因于概览条内）。
2. **状态先于结构**：任何状态下，用户最想知道的依次是 `签没签 → 成功还是失败 → 什么时候 → 详情`，层级按此排。
3. **点卡片=编辑只是基线，动作要能一跳直达**：单站签到 / 全站签到是一等公民按钮，不用再进弹窗。
4. **账号 ≠ 凭据堆**：界面话术永远用「账号」，只在编辑区出现字段标签。
5. **新站零前端成本**：站点声明从后端"长"出来，前端只剩渲染器。
6. **反馈即承诺**：动作按钮与结果 Toast 用同一套动词（"立即签到" → "签到完成"）；empty 是引导，失败是处方不是情绪。
7. **克制色、一源字体、层级用「行」而不用四周阴影**。

## 2. 信息架构与页面布局

### 2.1 整体架构：保持 3 Tab，不碎片化

`站点签到 / 运行设置 / 日志` 三个 Tab 保留。签到与设置是低频切换，日志主要是排障场景。**不新增第 4 个 Tab**——因为"签到结果"不是独立页面，而是主视图的第一信息层；把它塞进独立 Tab 会破坏"一天一瞥"的自然流。

站点页结构（自上而下）：

```
┌──────────────────────────────────────────────┐
│  站点签到                          [状态芯片] │  ← topbar
├──────────────────────────────────────────────┤
│  ┌ 今日签到 ─────────────── [立即签到全部] ┐  │  ← 总览条/台账头
│  │ ● 3/5 已签 · 剩 2 站未签               │  │
│  │  ✗ 恩山 09:12 人机验证 · 易破解 失败    │  │
│  └────────────────────────────────────────┘  │
│  [筛选: 全部|未签|失败|已停用]  [搜索站名…]    │  ← 6+ 站后出现
│  ┌────────────────────────────────────────┐  │
│  │  ▌恩 ┌─ 恩山无线论坛 ─────[已签]───[⇲] │  │  ← 站点行（台账行）
│  │  ▌   1 个账号 · Cookie                 │  │
│  │  ▌   ✓ 09:12 签到成功 · 今日积分：5    │  │
│  │  ▌   [立即签到] [编辑] [测试]           │  │
│  └────────────────────────────────────────┘  │
│  …（≥3 站时行内「▲ 展开账号」出现账号明细）   │
└──────────────────────────────────────────────┘
```

要点：
- **主视图第一眼 = 总览条**：今日 N/M 已签 + 失败名字（≤2 站直接并列，>2 站折叠为"+2 更多"或换行）。它是"账本头"，不是"统计卡片堆"。
- **每站一行**（台账行 / ledger row），不是高耸大卡片：10+ 站后竖向密度翻倍，滚动减半。
- 新站点尚在 0–3 个时，行自动加高、交互引导更充分（见 §3.2.1 空状态）。

### 2.2 站点多起来（10+）的组织方式

| 阶段 | 站点数 | 呈现 | 分组 | 筛选/搜索 |
|---|---|---|---|---|
| 启动 | 0–6 | 台账行 + 编辑引导 | 不需要 | 不需要 |
| 成长 | 6–12 | 台账行为主体 | **按"今天的状态"自动分组**（未签/已签/失败/已停用）最贴高频心智；辅以**自定义分组 tag**（`分组` 字段，默认空不显示） | 出**筛选 chips**（全部/未签/失败/已停用）+ 站名搜索框 |
| 规模 | 12+ | 同一组件，分组带头 | 自定义分组优先（未设分组的进「其他」） | chips + 搜索常驻 |

**设计决策**：
- **不用多列磁贴网格**。`grid-cards` 在 10+ 站时刷屏、每卡但见大片留白，且"账号行展开"深嵌套。台账行 + 窄列头像的密度远优于磁贴。
- 分组键支持两种来源：`今天状态`（零配置自动）与 `group`（用户手写）。自动分组永远先于自定义分组呈现。
- 搜索/筛选为**渐进增强**：`total > 6` 才渲染，避免新手区出现过重控件（skill：删掉任何不服务的面具）。

### 2.3 状态层级（一级/二级呈现）

一级 = 不展开卡片就能读懂的宏观状态；二级 = 展开/编辑后才进入的粒度详情。

| 层级 | 对象 | 呈现 |
|---|---|---|
| 一级 | 今日 N/M 已签 | 总览条 大数字 + 「剩 X 站未签」 |
| 一级 | 单站"今天签没签" | 行尾徽标：`已签 / 未签 / 失败` + 相对时间 `09:12` |
| 一级 | 全站动作 | `立即签到全部` primary |
| 二级 | 单账号状态 | 行内展开 → 每账号一行：备注 + 最近结果 + 测试/编辑 |
| 二级 | 失败详情 | Toast「失败原因」→ 点击展开 行内 `<details>` 显示 error 原文 |
| 二级 | 历史 | 日志 Tab（保持现状实时日志，行状态可点跳日志定位对账） |

失败的第二层信息默认不打断一瞥，但一行永远给"为什么"（error 文案已很口语：`Cookie 已失效，去设置里重新粘一份`）。

## 3. 关键交互流程设计

### 3.1 快速签到与结果反馈

#### 3.1.1 单站签到（两个入口互为备份）

```
[立即签到]（行内，一只 action 按钮，click.stopPropagation）
   │
   ├─ 按钮态：idle → "签到中…"（按钮内 spinner，可再点其他站/全部）
   ├─ POST /action/run  body={sites:["right_forum"]}   ← 后端已支持（server.js:99）
   ├─ 结果：收到 {success, data:{results:[{status,message,account,time}]}}
   ├─ ✓ 成功：行内徽标瞬时翻转 未签→✓已签 09:12；Toast「恩山 ✓ 签到成功 · 今日积分：5」3s
   ├─ ○ 今日已签到：徽标 → 印红"今日已签"；Toast「已签到过：今日积分：5」3s（中性色）
   └─ ✗ 失败：徽标 → ✗失败 09:12 + 单行 error 露出；Toast「恩山 ✗ 签到失败：人机验证挡住，过会儿再试」6s（红色、可点开看全文）
```

- 交互防误触：行剩余区域点击 = 展开/编辑；只有 `立即签到` 按钮本身触发签到；按钮用 `pointerdown` 区分与卡片 click，并用 `event.stopPropagation()`（现状 openSiteEditor 绑定在整卡 onclick，需改为卡片 `click` 事件 + 内部按钮 `stopPropagation`）。
- **并发**：单站签到可并行（不同站点互不依赖）；后端 `_running` 只锁「全部签到」，单站调用应**放开该锁**（改后端一行，见 §3.3 后端改动清单）；同一站的连点用前端 disabled 去抖即可。

#### 3.1.2 全站签到

- 总览条上的 `立即签到全部` = 现状 `runAll`，结果落点从角落文字（`runResult`）升级为：
  1. Toast：`签到完成 3/3 ·全部成功`（成功欢庆态盖"朱印")或 `1 站失败：恩山`；
  2. 总览条 N/M 实时 +1 动画；
  3. 行内徽标逐个落定。
- `runAll` 现在是整页一次大请求、等全部回来才写 `runResult`。保留"整体完成才汇总"的语义，但**每个站的必根据 results 逐行先落定**（`data.results` 本来就按站/账号顺序返回，前端拿到即可立即逐行渲染，不必等 .summary）。

#### 3.1.3 Toast 规范（统一反馈通道）

- 替换 `alert()`（现状 saveSiteModal / logClear 在用）；保留 `confirm()` 于删除等破坏性动作。
- 实现：单例 toast 容器，`showToast(kind, text, duration)`；bottom-center，`akenb` 品牌圆角。
- 语义：`success`（绿）、`info`（印红/中性）、`error`（红，自动 `duration=6s` + 可点击展开全文）。
- 动词一致性（skill：一个动作从头到尾同一个名字）：
  - `立即签到` → toast `签到完成`／`签到失败`
  - `测试` → `测试成功`／`测试失败：…`
  - `保存` → `已保存`；`删除` → `已删除`

### 3.2 站点与多账号的增删改路径

#### 3.2.1 空状态到建站的引导（cold start）

现状无站点时有空态 + `＋ 添加第一个站点`。建议空态升级为**引导魔法**：

```
┌────────────────────────────────┐
│  ▦                              │
│  还没有站点                       │
│  添加任意一个站点，每天自动签到     │
│  [＋ 添加第一个站点]              │
│  —————————— 或按类型直达 ————    │
│  [FLZT][恩山无线论坛][易破解][AnyRouter]  ← 直达按钮组（不弹窗选类型）│
└────────────────────────────────┘
```

「＋ 添加站点」弹选择器现状要两步（点添加 → 在弹窗里再点站点按钮）。空态下直接给**站点类型直达按钮**，点即进入该站点编辑弹窗，一步到位。

#### 3.2.2 新建站点 → 加账号 → 测试 → 保存 的最短路径

```
addSiteFlow 弹窗（选类型）／空态直达
   → 进入站点编辑弹窗（预填空账号区）
   → [新增账号] 出现一个空账号块
        ├─ auto-focus 第一个字段（email/base_url）
        ├─ 备注懒填：留空保存后 徽标/列表 用 `getAccountLabel` 摘要显示（掩码邮箱/Cookie）
        ├─ 回车 在最后输入框触发「保存」（form 语义；弹窗整体 Esc 关闭）
        ├─ [保存]（primary，缺省 Enter）
        └─ 保存成功后：Toast「已保存」；状态行 `st.textContent="已保存 ✓"→消失`；
             弹窗关；站点行出现并显示 `未配置` 或 `✓ 配置完成`
   → （可选）[测试] 按钮：调 test_login；成功 Toast「测试成功」，失败 Toast 给出可操作原因
```

**减距离的具体改动**：
- 弹窗加 `<form>` 语义：Enter 提交 = `saveSiteModal`，首个空输入 `autofocus`。
- 弹出即双开：`modalEnabled` 默认勾选新建站点（现状已在 addSiteFlow 设 true，保持）；`modalProxy` 保持 false。
- 新建站点时账号备注留空：卡片内账号行直接用 `label`（已掩码）作显示名，不再见空的备注框。
- 「保存」在账号数 >0 且站点 enabled 时才绿色高亮（primary），否则灰色提示（引导补全）。

#### 3.2.3 编辑路径

- 维持"点卡片主体 = 打开编辑弹窗"，但卡片被切成可点热区与纯展示区，见 §3.1.1 防误触。
- 弹窗内容基本保留现状（启用/代理开关 + 账号列表 + 新增/测试/删除），仅补充：字段级别 placeholder 帮助、@问题文案，以及保存成功后 Toast。
- **删除站点**（现状没有）：站点编辑归一为同一弹窗的"删除站点"危险区按钮（红色、confirm + `sites:[key]` 清空）。此操作应放入编辑弹窗，避免误删 adjacent。

### 3.3 新增站点类型的扩展机制（核心）

#### 3.3.1 现状成本审计（读码结论）

| 位置 | 改动 | 备注 |
|---|---|---|
| `sites.js` | 新增 adapter 对象 `{key,name,mode,fields,isConfigured,getAccountLabel,runCheckin,testConnection}` | **字段定义已存在且自描述** ✅ |
| `store.js` | `ADAPTERS` +1 行；`_migrateAccounts`/`saveConfig` 的**字段白名单**是私有 key 列表（`email/password/cookie/username/api_user/base_url`）→ 新字段类型（如 `captcha_token`、`uid`）要改这俩函数 | ⚠️ **白名单是硬伤** |
| `server.js` | 导出 `ADAPTERS` 处 `${FLZT,RIGHT_FORUM,YPOJIE,ANYROUTER}` +1 引用；`getConfig`/`status` 自动按 key 遍历，**无需改** | 部分自动 ✅ |
| `index.html` | `SITES` 字典手动加 `{name,tag,short,mode,desc,fields}`（约 8–12 行）；tag 类名是枚举 `t1..t4` | ⚠️ 前端元数据重复维护 |

结论：**新站前端要改 `SITES`，后端要改三处且字段白名单不透明。** 新站成本 ≈ 半小时，可接受；但 10 个站后变成"每次加站都要碰四份文件"。扩展性目标 = 把 `SITES` 与白名单消灭。

#### 3.3.2 目标架构：站点元数据单一事实源 = 后端 adapter

```
后端 sites.js：newAdapter = { key, name, mode, tag, desc, fields:[{key,label,type,ph}/…], isConfigured, …run 逻辑 }
        │  exports.ADAPTERS[key] = newAdapter        ← 唯一注册行
        ▼
store.js：ADAPTERS 从 sites.js 统一导出（serve.js 同源）
        └─ _migrateAccounts / saveConfig：字段白名单删除，
           改为按 adapter.fields 的 key 数组动态遍历（含敏感保留原文语义：
           空字符串 = 保留原值，照现状规则）
        ▼  get_config 新增加 adapter 元数据回传：
           sites[key].meta = { name, mode, tag, desc, fields, accountLabel }
        ▼            GET /action/get_config（已存在，仅扩展负载）
index.html：删除本地 SITES 字典 → 用返回的 meta 渲染：
           · 账号表单 = fields 数组驱动（现状 renderSiteCards/openSiteEditor/accountRowEl 已按 fields 渲染，改数据源即可）
           · tag 色 = 后端给 hint 值或按键名 hash 轮转调色板（消灭 t1..t4 枚举）
```

**前端零改动接入对照表（目标态）**：

| 动作 | 现状 | 目标 |
|---|---|---|
| 新增一种站点类型 | 改 sites.js + store.js 白名单 + server.js 引用 + index.html SITES + tag 配色 | 只改 sites.js、注册 1 行 |
| 新站点带全新字段类型 | 白名单再改两处 | 无需改动 |
| 前端不认识的旧数据下发 | 渲染 `undefined` | `get_config` 按 fields 过滤 + 多写合并，安全退化 |

**落地顺序（改造）**：
1. **只读源移入后端**：`get_config` 回传 `meta`（name/mode/tag/desc/fields/accountLabel）。前端优先用 meta，`SITES` 保留作为兜底并随后删除。**本步完成即达成"新站零前端成本"。**
2. **后端统一 `ADAPTERS`**：`store.js` 从 `sites.js` 取 `ADAPTERS`（消除一份拷贝），`server.js` 同步。
3. **字段动态化**：`store._migrateAccounts` / `saveConfig` 改为读 adapter.fields 的 key 集；保留 `空串=保留原值` 与 `password/cookie 留空不改` 的既有规则；后端新增 `getAccountLabel` 摘要已具备。
4. **前端渲染器解偶**：`SITES` → meta；`tag` 用 `hsl(v[k]*137) ` 按键名轮转（或 meta.tag 色板）。

> 后端/结构性改动均落在 checkin 各 `.js`，本轮仅设计、不实施。P0 不包含第 3、4 步（见 §5）。

#### 3.3.3 新增站点时的检查清单（写进 README / 培训材料）

```
□ sites.js：新增 adapter → 一定实现 isConfigured / getAccountLabel（决定卡片与账号标签）
□ 字段敏感级：password/cookie → 沿用「留空=保留原值」；明文字段保留现状存储
□ getAccountLabel 的语料 = 卡片唯一显示名（希望展示什么，就返回什么）
□ runCheckin 失败统一 throw Error（供历史 + 卡片败因展示）
□ 语言一致性：status 文案沿用「签到成功/今日已签到/执行失败」三分（isAlreadyCheckedIn 已汇总）
```

### 3.4 最近签到状态的持久化与展示

#### 3.4.1 推荐：派生视图（cheap & robust）

`checkin_history.json` 已记录**每次成功与失败**（server.js:117,122）。「最近签到结果」可以从历史**派生**：

```
GET /action/status（已存在）
  data.sites[key].last = { date, status, message, account_label, time }  
  // 从 store.getHistory() 取该 site_key 的第一条非空记录（最近一条）
  // 若 time 的日期 == 今天 → status 归一为 已签/失败/未签
GET /action/status（全量合成）
  data.today = { done, total, failed: [key…] }
```

优点：不加持久化字段、零迁移、历史天然保留完整对账链条。只读函数，无写入。

**分批建议**：
- **不新增 `last_checkin` 落盘字段**（除非后续要跨天统计/图表，再考虑 `store` 加 `per_day_status: {date: {site:{status}}}`,但那是 P2 之后的延伸）。
- 只读派生后，卡片/总览逻辑为纯前端状态合并：
  ```js
  function mergeStatus(sites){ return sites.map(s=>
    ({...s,
      today: s.last && sameDay(s.last.time, new Date())
        ? okStatus(s.last)       // 已签 | 今日已签到 | 失败 | 未签
        : "未签",                 // 非今天记录一律显示"未签"
      last: s.last
    }))}
  ```

#### 3.4.2 展示规则

| 徽标 | 含义 | 样式 |
|---|---|---|
| `✓ 已在 09:12 签到` | 今日成功 | 绿点 + 绿字 |
| `🕒 今日已签到` | 今日重复签到（无新奖励） | 印朱色 outline（"已盖章"） |
| `✗ 失败 09:12` | 今日失败 | 红点 + 摘要可在行内 `<details>` 展开 |
| `未签` | 无今日记录 / 停用 | 灰点 |

- 站点默认只显示**聚合**：全部账号状态取"最坏优先"（任一失败→失败；否则任一已签成功→成功；否则今日已签→已签；否则未签）；展开后逐账号明细。
- 跨天自动刷新：页面 init + `setInterval(30s)`（现状已有 30s get_config 轮询，复用同 tick 刷新 last/today 即可）。

## 4. 视觉规范建议

### 4.1 色彩系统（CSS 变量）

**概念**：`纸面（灰白）＋ 墨（蓝灰）＋ 朱印（品牌/庆祝）＋ 三状态色（绿/琥珀/红）`。朱印只在构成"盖章时刻"的位置出现，状态红用更暗的绯红以免混淆（**失败红只出现在错误/警告语境，绝不与品牌朱印同屏撞色**——品牌朱印在总览/CTA，失败绯红在徽标/文案）。

  --seal:#C8452A;               /* 朱印红（偏暗的印泥，非鲜橙红） */
  --seal-strong:#A4341D;
  --seal-soft:rgba(200,69,42,.1);
  --badge-seal:rgba(200,69,42,.14);

  /* 状态三色 */
  --ok:#1E8A4E;   --ok-glow:rgba(30,138,78,.16);   --ok-border:rgba(30,138,78,.4);
  --warn:#B7791F; --warn-bg:#FBF1DC;

TS/语义映射：
- 品牌主色 = `--seal`（现状 `--accent:#1E88E5` 全面替换：brand-mark、primary CTA、active nav、focus 都要换；`--accent` 变量名保留给内部引用避免大改，只换值 → 侵入最小）。
- `--ok/green` 保持现状值即可（现状 #178A52/#34C07B 已健康）。
- **改法提示**：现状 `:root` 已有 `--accent`，P0 即把 `--accent/--accent-strong/--accent-soft/--focus` 替换成上表朱印值，全局品牌有辨识度，其余建筑类 `--bg/--card/--ink/--border` 不动，改动面小。

### 4.2 字体与节奏

- **一族字体，不引入 display 字体**：沿用 `system-ui, …"PingFang SC","HarmonyOS Sans SC"…`，但把字号/字重做成节奏表，标题与正文同族、仅用字重/字号做层级。
- mono 只给**时间戳/版本/账号摘要**用（现状已 mono）。
- 字号尺（相对现状微调）：

| token | 值 | 用在哪 |
|---|---|---|
| `--fs-xs` | 11px | 标签、徽标、侧栏元数据 |
| `--fs-sm` | 12.5px | 描述、次级文案 |
| `--fs-base` | 14px | 正文/默认 |
| `--fs-lg` | 16px | 站点名、弹窗标题 |
| `--fs-xl` | 22px | 总览"今日 N/M"大数字 |
| `--fs-2xl` | 30px | 仅空态引导 |

- 行高 `1.55` 保持；正文行宽 `< 72ch`；标题不加粗（700 上限）+ 不加 all-caps eyebrow + 不加中点连接。侧栏 `brand-sub` 现状 `FLZT · 恩山 · 易破解` 是"meta 中点串"→ 改为纯名称列 `FLZT / 恩山 / 易破解`（仍可保留，但作为产品清单而非 decorative）。

### 4.3 间距与结构层次

- 用 **8 点网格**：外距 24/28、卡片内 16、行间 10–12、徽标空间 6。
- 层级不再靠阴影叠（现状每卡统一 shadow = SaaS 卡套件味），改为**台账线**：`border-top:1px solid var(--border)` 的分行结构 + 仅对"当前展开/悬浮"的行给 `--shadow`。
- 首屏总览条是仅有的"大块"（`background:var(--card)` + 1px 边框），其余站点行保持轻量边框。
- 空状态/空白区 = 引导（btn 直达），不堆装饰插图。

### 4.4 动效（克制，回答动作）

- **只用动作回映**：签到成功时徽标一次 `stamp` 缩放（180ms ease-out，动效本身像盖章）；失败时行内 error `<details>` 展开微滑 120ms。取消所有"入场 fade+slide"与逐卡 hover 过渡。
- 遵循 `prefers-reduced-motion`：`@media (prefers-reduced-motion: reduce){ *{transition:none !important; animation:none !important} }`。
- 刷新"N/M"数字变化时 160ms ease。
