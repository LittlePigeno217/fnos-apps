## 1. 审查范围与结论摘要

### 1.1 覆盖范围

| 应用 | 后端 action 路由 | 业务链路追踪 | UI 界面适配检查 |
|---|---|---|---|
| p115assistant | 44 个 action + `/redirect` 逐一核对（action→handler→实现→前端引用） | 登录/扫码、上传（秒传/增量/实时监听）、STRM 生成与 302 取链、签到、历史/媒体账本、热更/更新、风控三档 | 移动端/暗色/响应式/字体/可达性静态检查 |
| checkin | 11 个 action 逐一核对 | 4 个站点 adapter、定时+补签调度、飞书通知、历史/日志、弹窗编辑、今日总览、热更 | 同上 |

### 1.2 总体结论

- **后端路由体系健康**：两应用所有 action 均能映射到已实现的 handler，无拼写不一致、无未导出 handler。checkin 未发现 `$("#")` 类选择性器低级错误残留。
- **热更链路当前健康**：两应用部署端 `server/*.js` 与 `www/index.html` 哈希与 `runtime-manifest.json` 完全一致；`get_config`/`check_hotfix` 返回的功能版本与运行时一致。
- **但存在两类系统性隐患**：
  1. **checkin 配置合并逻辑**（`store.js` 的 `_mergeDefaults` / accounts 合并）存在 1 个 P0 级凭据串号风险（一次保存新增多个账号即触发）、1 个热更版本号被覆盖的死代码链路。
  2. **两条"已实现但未接线"子系统**：p115 的媒体账本（ledger）与 FPK 自更新整条链路无任何前端入口；checkin 的 `history/history_clear` 为死路由。
- **界面适配**：暗色体系基本完整，但两应用各有一个未定义 CSS 变量（p115 `--surface`；checkin `--danger`，p115 的 `--danger` 也未定义）导致硬编码色残留；checkin 存在两个确定的视觉缺陷（站点 tag 类名不匹配失明、品牌渐变残留旧蓝）。移动端整体风险低，唯 checkin 顶栏 chip 在 ≤340px 有溢出风险（未实测）。
